# Transcript-only study

The artifact study screen uses saved text even when an analysis provider is unavailable. Saved text changes the legacy red transcription error into a nonblocking analysis warning; redundant paste/fetch actions are hidden. Retrying enhanced analysis is explicit. An active legacy job with saved text has a compact pending status, not a misleading transcript-fetch animation.

A client-side worker scans the saved transcript without provider requests, model downloads, database changes, or new dependencies. It suggests up to six unedited excerpts across the source, ordered by source position, and detects explicitly written Scripture references using known book/chapter bounds. Repeated-word frequency, written references and source position are selection signals, not proof of importance, truth, or theological support. References are mentions, not verified verse wording. Excerpt line breaks are joined; text is not paraphrased or given a new interpretation. Estimated/absent timestamps remain estimated/absent.

The panel is automatic when findings are absent or analysis is unavailable; it is optional/collapsed alongside successful findings. Timestamp actions use the existing player callback and never autoplay without a click. Manual Copy copies the excerpt only. The results are kept in memory and are source-scoped. Source changes/navigation/unmount cancel work and ignore late messages. Local results do not write artifact status, claims, verdicts, or research history and never mark AI analysis complete.

Limits: sources above one million characters are explicitly declined rather than truncated. Worker failure falls back to deferred local computation for sources at most 100,000 characters; larger sources retain reading/search/notes with an explicit local-scan limitation. A worker watchdog bounds stalled work. Existing transcription, model billing and durable backend deployment requirements are unchanged. This patch does not install or deploy backend migrations/functions or re-analyze the library.

Validation: unit tests cover literal extraction, scope/negation, long-source coverage, exact duplicates, written references, untimed/coarse timings and size limits. Hook/component regressions cover zero provider calls, navigation/source-change cancellation, worker-unavailable behavior, explicit seeks/copies, legacy/provider/partial states, and preservation of real analysis status. Physical-device acceptance still requires desktop and iPhone playback checks.
